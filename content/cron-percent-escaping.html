Cron: The % Sign Trap

In crontab, a bare % is converted to a newline and everything after it is stdin. Learn the \\% escape rule with real examples.

The single most confusing crontab behavior: a bare % in the command portion is converted to a newline, and all data after the first % is fed to the command as standard input.

What actually happens

You writeCron executes
date +\%Fdate +%F ✓
date +%Fdate + with %F on stdin ✗ (error or wrong output)
echo done % commentecho done with " comment" on stdin

The rules

1. Escape every literal percent as \% in the command part of a crontab line.
2. Everything after the first unescaped % becomes stdin — useful for piping fixed input: mail admin@x.com % Backup failed sends "Backup failed" as the message body.
3. This applies to crontab lines only — systemd timers, shell scripts and most schedulers treat % normally.

Real-world breakage

The classic casualty is a month-end guard: [ "$(date +\%d)" = "01" ] && job — forget the escape and the guard never matches, the job never runs, and nothing logs an error.
