Cron 环境变量：为什么命令行能跑，crontab 里就失败

Cron runs with a minimal environment: default PATH, no shell profile, SHELL=/bin/sh. Why scripts work in your terminal but fail in cron — and the four standard fixes.

一句话原因：cron 不读取你的 shell 配置文件（.bashrc / .bash_profile），用最小环境执行任务。

cron 环境与登录 shell 的差异

变量登录 shellcron
PATH完整（含 /usr/local/bin 等）通常仅 /usr/bin:/bin（Debian/Ubuntu）
SHELL你的默认 shell/bin/sh
HOME用户家目录已设置
自定义变量/别名来自 .bashrc 等无

典型症状

命令行执行成功，cron 里报 command not found（PATH 缺失）或行为不同（SHELL 是 sh 不是 bash）。

四种标准修复

1. crontab 顶部设 PATH：

PATH=/usr/local/bin:/usr/bin:/bin
SHELL=/bin/bash

2. 命令用绝对路径——最稳：/usr/local/bin/python3 /opt/job/run.py。

3. 包一层登录 shell（继承 profile 环境）：bash -lc '/opt/job/run.sh'。注意登录脚本里别有交互式输出。

4. 脚本内部显式 export 需要的变量，不依赖外部环境。
