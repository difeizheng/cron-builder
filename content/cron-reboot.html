Cron: Run a Job at Reboot (@reboot)

@reboot runs a command when cron starts. Syntax, why it may not fire after reboot, environment differences, and alternatives for systemd systems.

@reboot /path/to/your/script.sh

@reboot replaces all five time fields: the command runs once when cron daemon starts — typically at system boot.

Why your @reboot job silently doesn't run

CauseFix
cron daemon wasn't restarted — it only fires when cron itself starts, not when you log insudo service cron restart to test
Relative paths break — @reboot runs from $HOME with a minimal PATHUse absolute paths everywhere
Network isn't up yet — the job races the network stackAdd sleep 30 && before the command
You edited user crontab but the job is in /etc/crontab — syntax differs (user field required)Check which crontab you edited: crontab -l

Alternatives on modern systems

On systemd distributions, a unit with Type=oneshot + WantedBy=multi-user.target is more reliable than @reboot: it integrates with logging, dependencies (After=network-online.target), and restart policies. Use @reboot for quick personal scripts; use systemd units for anything production-adjacent.
