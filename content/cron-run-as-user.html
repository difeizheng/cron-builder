以其他用户身份跑 cron：/etc/crontab 的用户字段

How to run cron jobs as a different user: the user field in /etc/crontab and /etc/cron.d, why sudo doesn't work in user crontabs, and the right patterns.

用户自己的 crontab -e 没有用户字段——任务永远以你自己身份跑。想以别的用户跑，要用系统级 crontab。

/etc/crontab 与 /etc/cron.d/*：多一个用户字段

# 分.时 日 月 周 用户 命令
0 3 * * *  www-data  /usr/bin/php /var/www/cron.php
*/10 * * * *  postgres  /opt/scripts/vacuum.sh

注意与用户 crontab 的格式差异：命令前多了用户名。/etc/cron.d/ 下每个文件都遵循同样格式（文件名不允许含点、必须是 root 属主、权限 644）。

为什么 crontab 里写 sudo 会失败

用户 crontab 里的 sudo cmd 需要终端输入密码（cron 无 tty），直接失败。替代方案：

场景正确做法
以其他普通用户跑写进 /etc/cron.d/ 并指定用户字段
以 root 跑sudo crontab -e 编辑 root 自己的 crontab
个别命令需提权sudoers 精确授权：myuser ALL=(root) NOPASSWD: /opt/job/run.sh

环境与权限的连带差异

换个用户跑，HOME/PATH/文件权限全变——脚本里引用的日志目录、配置文件要对目标用户可读写。环境变量残缺问题在系统 crontab 里同样存在。
