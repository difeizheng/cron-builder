Cron: Timezone — The Silent Schedule Killer

Cron runs in the server's timezone. How to check it, set CRON_TZ, handle UTC servers from China, and DST-free zones.

A 0 9 * * * job runs at 9 AM server time — which may be nobody's morning. Timezone mismatches are the #1 cause of "my cron runs at the wrong time".

Check and fix

TaskCommand
See server timedate or timedatectl
Set server timezone (Debian/Ubuntu)sudo timedatectl set-timezone Asia/Shanghai
Per-job timezone (cronie, Vixie cron)CRON_TZ=Asia/Shanghai line above the job
systemd timersOnCalendar=*-*-* 09:00:00 Asia/Shanghai

UTC server, China morning job

09:00 Beijing = 01:00 UTC → write 0 1 * * * on a UTC server, or set the timezone explicitly. Doing the math by hand for every job is error-prone; the conversion table approach fails when DST exists (China has none, but US/EU servers shift twice a year).

DST note

China has no daylight saving, but a job scheduled on a US/EU server will jump an hour twice a year unless the timezone is pinned. Prefer pinning the server or job timezone over hard-coding UTC offsets.
